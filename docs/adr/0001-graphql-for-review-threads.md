# GraphQL for review threads only, with a REST fallback that fails closed

Everything the factory does on GitHub goes through `gh api` over REST, never GraphQL, because Claude Code cloud sessions can't reach GraphQL. The one exception is the human lens (#57): whether a review thread is resolved is only in GraphQL, so `pr-comments.mjs` reads the threads with one `gh api graphql` query and `pr-resolve.mjs` resolves a thread with `resolveReviewThread`. Nothing else may call GraphQL.

Where GraphQL is refused or out of reach, or its answer is truncated (the query takes 100 threads, comments in a thread and reviews, and any of them reports `hasNextPage`), `pr-comments.mjs` reads every page of the PR's review comments, reviews and PR comments over REST, stopping rather than reading part of a list, and builds the same findings under the same ids and trust rules, with every thread unresolved, since REST can't say otherwise. It fails closed: a thread the human resolved stays open, and one the factory answered last waits as an ask, so nothing is skipped. `pr-resolve.mjs` still replies with the SHA over REST and records the answer in `review-human.md`, but leaves the thread open on GitHub. The rejected alternative, treating the factory's own record of what it answered as GitHub's state, would let a thread the human reopened pass unseen.
