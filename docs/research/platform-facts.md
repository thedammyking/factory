# Which Claude Code platform facts still hold for the factory?

Ticket: [#2](https://github.com/thedammyking/factory/issues/2). Checked 2026-11-02 against the raw Markdown of the official docs at code.claude.com and the changelog (latest entry 2.1.316, 31 Oct 2026: <https://code.claude.com/docs/en/changelog>). Background: [design.md, "Claude Code's plugin rules shape every design choice"](https://github.com/thedammyking/factory/blob/main/docs/design/design.md#claude-codes-plugin-rules-shape-every-design-choice).

## Answer

- Most facts hold: plugin hooks reach subagents, `SubagentStart` is the injection path, plugin agents ignore `hooks`/`mcpServers`/`permissionMode`, and `${CLAUDE_PLUGIN_ROOT}` is absent from Bash.
- Six need correction: `AskUserQuestion` is conditional under `-p`, not absent; a subagent's `totalTokens` is its final request only, not spend; `isolation: worktree` branches from the default branch, not the feature branch; the `verify` pre-commit skill must live in the project, not the plugin; the sandbox is opt-in and Chromium fails only on Linux/WSL2; a plugin cannot set `sandbox.excludedCommands`.
- Two capabilities exist that the design does not mention: plugin-to-plugin `dependencies` and `claude plugin eval` (since 2.1.269, 11 Sep 2026).
- The design should keep its hook-based architecture and change worktree base, budget metering, verify placement, headless questions and sandbox exclusion (see "Implications").

## Findings

Verdicts: **HOLDS**, **CHANGED** (was true, no longer), **CORRECTED** (the design's wording was wrong or incomplete), **NEW**.

### 1. Hooks and subagents

- **HOLDS.** Plugin hooks run inside subagents. "Hooks from settings files, managed policy settings, and plugins also run inside subagents"; tool events carry `agent_id` and `agent_type` ([hooks](https://code.claude.com/docs/en/hooks)).
- **HOLDS.** `SessionStart` context does not reach a subagent. A non-fork subagent starts with its system prompt, the task message, the CLAUDE.md hierarchy, a git-status snapshot, preloaded skills and a sibling roster, and nothing else ([sub-agents, "What loads at startup"](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup)).
- **HOLDS.** `SubagentStart` fires on spawn, on resume, and on each agent-team teammate message. For plugin agents the matcher value is the scoped id (`^factory:implementer$`), not the bare name. Its only output is `additionalContext`, "added to the subagent's context at the start of its conversation, before its first prompt"; it cannot block creation ([hooks, SubagentStart](https://code.claude.com/docs/en/hooks#subagentstart)). The event was added in 2.0.43 ([changelog](https://code.claude.com/docs/en/changelog)).
- **NEW detail.** Handler types for `SubagentStart` are `command`, `http` and `mcp_tool` only; `prompt` and `agent` hooks are rejected, and `SessionStart` accepts only `command` and `mcp_tool` ([hooks, prompt-based hooks](https://code.claude.com/docs/en/hooks#prompt-based-hooks); 2.1.142 in the changelog).
- **NEW detail.** `additionalContext` is capped at 10,000 characters per field. Over the cap, Claude Code writes it to a session file and passes the path plus the first 2,000 characters, and the cap has no setting. Values from several hooks are all delivered. Docs advise factual phrasing, since imperative "system" wording can trip prompt-injection defenses ([hooks, add context](https://code.claude.com/docs/en/hooks#add-context-for-claude)).
- **NEW detail.** On re-runs for the same subagent the context is re-injected only if the subagent no longer holds it (for example after auto-compaction); 2.1.265 fixed a bug that moved it out of the cached prefix ([hooks](https://code.claude.com/docs/en/hooks#subagentstart); [changelog](https://code.claude.com/docs/en/changelog)).
- **NEW.** `PreToolUse` can return `allow`/`deny`/`ask`/`defer`, `updatedInput` (replaces the whole input) and `additionalContext` ([hooks, PreToolUse](https://code.claude.com/docs/en/hooks#pretooluse)). By default a failed or timed-out hook lets the action proceed; `"onFailure": "block"` (2.1.295+) makes a command or http hook fail closed ([hooks](https://code.claude.com/docs/en/hooks#block-the-action-when-a-hook-fails)).
- **NEW.** `SubagentStop` input has `agent_id`, `agent_type`, `agent_transcript_path` and `last_assistant_message`, and a handler can keep the subagent running with `additionalContext` or `decision: "block"`. To push context into the parent, use a `PostToolUse` hook on the `Agent` tool ([hooks, SubagentStop](https://code.claude.com/docs/en/hooks#subagentstop)).

### 2. Subagent frontmatter in plugin agents

- **CORRECTED (incomplete).** Plugin agents support `name`, `description`, `model`, `effort`, `maxTurns`, `autoCompactWindow`, `tools`, `disallowedTools`, `skills`, `memory`, `background`, `omitClaudeMd`, `isolation` (only `"worktree"`), `color` and `experimental.cacheTtl`. They ignore `permissionMode`, `hooks`, `mcpServers` **and `initialPrompt`**. Unknown fields are ignored without an error; unparseable frontmatter loads the agent with every field ignored and a generic description ([plugin components, agents](https://code.claude.com/docs/en/plugins/components#frontmatter-fields-in-plugin-agents); [sub-agents, fields](https://code.claude.com/docs/en/sub-agents#frontmatter-reference)).
- **HOLDS.** `model` takes `sonnet`, `opus`, `haiku`, `fable`, a full ID or `inherit`. `maxTurns` ends the run with partial output that can be resumed (2.1.246). `effort` takes `low` to `max`, is overridden by `CLAUDE_CODE_EFFORT_LEVEL`, and `CLAUDE_CODE_SUBAGENT_EFFORT` (2.1.316) sets the default for subagents ([sub-agents](https://code.claude.com/docs/en/sub-agents#frontmatter-reference); [changelog](https://code.claude.com/docs/en/changelog)). `memory: project` writes `.claude/agent-memory/<agent>/`, injects the first 200 lines or 25 KB of `MEMORY.md`, and auto-enables Read/Write/Edit ([sub-agents, memory](https://code.claude.com/docs/en/sub-agents#enable-persistent-memory)).
- **CORRECTED.** `isolation: worktree` branches from `origin/<default-branch>`, "rather than the parent session's `HEAD`", unless `worktree.baseRef` is `"head"`. The worktree is deleted if the subagent changed nothing, and commands that resolve to the main checkout are refused ([sub-agents, isolation](https://code.claude.com/docs/en/sub-agents#frontmatter-reference); [settings, worktree.baseRef](https://code.claude.com/docs/en/settings-reference#worktree-baseref)). A plugin cannot set it (see 3b).
- **HOLDS.** Concurrency cap 20 (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`) and spawn depth 3 (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`), both configurable ([sub-agents](https://code.claude.com/docs/en/sub-agents#concurrent-subagent-limit)). The single-agent guidance quoted in the design is still in the page ([choose between subagents and main](https://code.claude.com/docs/en/sub-agents#choose-between-subagents-and-main-conversation)).
- **NEW.** Fork mode is on by default from 2.1.302. A fork inherits the full conversation and shares the parent's prompt cache; while it is on, Claude cannot wait for a subagent in interactive sessions ([sub-agents, fork](https://code.claude.com/docs/en/sub-agents#fork-the-current-conversation)). Combined agent descriptions over 15,000 tokens give a startup warning only ([sub-agents](https://code.claude.com/docs/en/sub-agents#understand-automatic-delegation)).
- **NEW.** `skills:` preload injects full content (first 32 names) but "you can't preload skills that set `disable-model-invocation: true`" ([sub-agents, preload](https://code.claude.com/docs/en/sub-agents#preload-skills-into-subagents)).

### 3. Where `${CLAUDE_PLUGIN_ROOT}` and `${CLAUDE_PLUGIN_DATA}` resolve

Source for the table: [manifest reference, environment variables](https://code.claude.com/docs/en/plugins/manifest-reference#environment-variables); [skills, substitutions](https://code.claude.com/docs/en/skills#available-string-substitutions).

| Place | Substituted | Exported as env var |
| :- | :- | :- |
| Hook `command` and `args` | Yes, anywhere | Yes (`CLAUDE_PLUGIN_ROOT`, `CLAUDE_PLUGIN_DATA`, `CLAUDE_PROJECT_DIR`) |
| Monitor commands | Yes | No |
| MCP `stdio` `command`/`args`/`env`; LSP servers | Yes | Yes |
| Skill, command and agent Markdown body | Yes, inline when loaded (plugin skills only) | n/a |
| Skill `allowed-tools` Bash rules | Yes (plugin skills) | n/a |
| Commands Claude runs through Bash, main or subagent | **No**: "the variables aren't present in the environment" | No |

- **HOLDS.** Nothing may be stored under `${CLAUDE_PLUGIN_ROOT}`; it changes per version (`cache/<marketplace>/<plugin>/<version>/`). `${CLAUDE_PLUGIN_DATA}` is `~/.claude/plugins/data/<id>/`, created on first reference, kept across updates, deleted on last uninstall unless `--keep-data` ([loading](https://code.claude.com/docs/en/plugins/loading#find-plugins-on-disk)). `${CLAUDE_SKILL_DIR}` in a plugin skill is the skill's own folder, not the plugin root ([skills](https://code.claude.com/docs/en/skills#available-string-substitutions)).
- **NEW (bridges for Bash).** (a) `bin/` at the plugin root is put on the Bash tool's `PATH` while the plugin is enabled, after the user's own entries; claude.ai and Cowork refuse to install a plugin that has it ([components, executables](https://code.claude.com/docs/en/plugins/components#executables)). (b) A `SessionStart` or `Setup` hook can append `export` lines to `CLAUDE_ENV_FILE`, which persist "for the shell commands Claude runs later in the session" ([hooks, persist environment variables](https://code.claude.com/docs/en/hooks#persist-environment-variables)). Whether (b) also reaches a subagent's Bash is **not documented**; test before relying on it.
- **Unverified.** The design cites ECC notes that declaring `agents` or `hooks` in `plugin.json` caused "Duplicate hooks file" errors. The official docs do not mention that error; they say a declared `hooks` value is merged with `hooks/hooks.json` ([manifest reference, hooks](https://code.claude.com/docs/en/plugins/manifest-reference#hooks)). Omitting both keys remains the safe choice.

### 3b. What a plugin can set in settings

**HOLDS, and matters later.** A plugin's `settings.json` (or `settings` key) honours only `agent` and `subagentStatusLine`; "every other key is dropped" ([components, default settings](https://code.claude.com/docs/en/plugins/components#default-settings)). So a plugin cannot set `worktree.baseRef`, `sandbox.*` or permissions.

### 4. Skills: invocation flags, listing budget, size, compaction

- **HOLDS.** `disable-model-invocation: true`: description not in context, user can run `/name`, Claude is told to ask the user to run it (2.1.222). `user-invocable: false`: hidden from the `/` menu, Claude can still invoke it, description stays in context ([skills, control who invokes](https://code.claude.com/docs/en/skills#control-who-invokes-a-skill); [changelog](https://code.claude.com/docs/en/changelog)).
- **CORRECTED (citation, not fact).** The listing budget is documented on the skills page: 1% of the context window; `description` plus `when_to_use` capped at 1,536 characters per entry; overflow drops descriptions starting with the least-invoked, names always stay. Raise it with `skillListingBudgetFraction`, `skillListingMaxDescChars` or `SLASH_COMMAND_TOOL_CHAR_BUDGET` ([skills, listing](https://code.claude.com/docs/en/skills#skill-descriptions-are-cut-short)). `skillOverrides` does not apply to plugin skills ([skills](https://code.claude.com/docs/en/skills#find-unused-skills)).
- **HOLDS.** Compaction re-attaches each invoked skill's latest invocation, "keeping the first 5,000 tokens of each", within a combined 25,000 tokens, filled from the most recent, so older skills can drop out entirely ([skills, lifecycle](https://code.claude.com/docs/en/skills#skill-content-lifecycle)). `SKILL.md` size: "keep under 500 lines" is guidance, not an enforced limit ([skills](https://code.claude.com/docs/en/skills#add-supporting-files)).
- **CORRECTED.** The "free `verify` gate" works only for a skill in the enterprise, personal, project or additional-directory location or `.claude/commands/`. "Plugin skills ... don't count." It must also be model-invocable and `includeGitInstructions` must be on. Needs 2.1.286+ ([skills, run your checks before each commit](https://code.claude.com/docs/en/skills#run-your-checks-before-each-commit)).
- **NEW.** `claude plugin details <name>` prints a plugin's projected always-on token cost ([measure](https://code.claude.com/docs/en/plugins/measure#measure-what-a-plugin-costs)); `/skill-doctor` (2.1.252+) reports unused skills.

### 5. Plugin dependencies

- **CHANGED: yes, a plugin can depend on another.** `plugin.json` takes `dependencies`: a name, `name@marketplace`, or `{name, version, marketplace}` where `version` is a semver range resolved against git tags named `<plugin>--v<version>`. Install also installs and enables dependencies at the same scope; `plugin disable` refuses while a dependent is enabled (2.1.143); auto-installed dependencies stay until `claude plugin prune`; cross-marketplace dependencies need the root marketplace's `allowCrossMarketplaceDependenciesOn` ([dependencies](https://code.claude.com/docs/en/plugins/dependencies); [install](https://code.claude.com/docs/en/plugins/install#plugins-with-dependencies)). Dependencies are mandatory; there is no optional form.

### 6. How a parent learns a subagent's token usage

- **CORRECTED.** For a foreground subagent the parent's `PostToolUse` hook on the `Agent` tool receives `tool_response` with `totalTokens`, `usage`, `totalDurationMs`, `totalToolUseCount`, `agentId`, `resolvedModel`. But `totalTokens` and `usage` "cover the final request only", not the run. Background subagents return `async_launched` with no usage ([hooks, Agent](https://code.claude.com/docs/en/hooks#agent)). `SubagentStop` carries no usage fields ([hooks](https://code.claude.com/docs/en/hooks#subagentstop)).
- Cumulative spend lives elsewhere: OpenTelemetry token and cost counters filtered to `query_source` `"subagent"` (needs `CLAUDE_CODE_ENABLE_TELEMETRY=1` and an exporter) ([monitoring](https://code.claude.com/docs/en/monitoring-usage#subagent-completed-event)); and in headless/SDK results, `total_cost_usd` and `modelUsage` include subagents while `usage` excludes them ([cost tracking](https://code.claude.com/docs/en/agent-sdk/cost-tracking)). `claude -p --output-format json` returns `total_cost_usd` and a per-model breakdown, both client-side estimates ([headless](https://code.claude.com/docs/en/headless#pipe-data-through-claude)).
- The subagent transcript path is documented (`agent_transcript_path`; [sub-agents](https://code.claude.com/docs/en/sub-agents)). Its lines carry per-message `usage` objects (observed in a local transcript on 2026-11-02), but the docs do not specify the format, so summing them is best-effort.

### 7. `claude plugin eval`

Source: [plugin evals](https://code.claude.com/docs/en/plugin-evals). Added in 2.1.269 ([changelog](https://code.claude.com/docs/en/changelog)).

- **What it runs.** Per case, per run (default 3), a fresh isolated `claude -p` child with only the plugin loaded, in a temporary HOME, cwd and config. User settings, CLAUDE.md, other plugins, memory and project `.claude/` are not loaded. The plugin's hooks and agents do run. By default each case also runs a no-plugin baseline arm; `Δ` is with minus without. The Artifact tool is off and the case files are hidden from the agent.
- **Cases and limits.** `evals/<case>/prompt.md` plus `graders/*.md` (or `case.yaml`). `max_turns` default 10 (max 200), `timeout_seconds` default 300 (max 3600), `runs` 1 to 50. The workspace starts empty; a `scaffold_script` (120 s, only with `--scaffold`) can create files and git state.
- **Tools.** Only the read-only set listed in a case is available. `Bash`, `Write`, `Edit`, `WebFetch` need `--allow-tools`; Bash then runs in the OS sandbox (macOS, Linux with bubblewrap and socat, WSL2; no native Windows). Plugin MCP servers are mocked unless `--allow-real-servers`.
- **Graders.** Free: `regex`, `tool_used`, `tool_order`, `file_exists`. Judged (2 of 3 votes): `llm`, `baseline`. No custom-code graders. `tool_used: Skill` graders are indicators, not scored, in two-arm runs.
- **Reporting.** A summary table (`WITH`, `W/OUT`, `Δ`, `RUNS`, `COST`, `NOTES`), `results/<timestamp>/aggregate-result.json` (`schemaVersion: 1`) and a self-contained `report.html`; published as a private artifact for subscription logins unless `--no-publish`. Exit 0 pass, 1 below `--threshold` (default 1.0) or load/API failure, 2 partial (cost ceiling or rejected credential), 130/143 interrupted. `Δ` never changes the exit code. Pin `--model`/`--judge-model` in CI and cap with `--max-cost-usd`. Every run and judge call is billed.
- **Gotcha.** In the baseline arm, dispatching a plugin agent fails with "Agent type ... not found", which is expected; use `--ablation none` for agent-heavy cases.

### 8. Plugins and skills under `claude -p`

- **HOLDS.** Without `--bare`, `-p` loads hooks, skills, subagents, plugins, MCP servers and CLAUDE.md like an interactive session. `--bare` skips all auto-discovery (load a plugin with `--plugin-dir` or `--plugin-url`), omits the skill list from context, blocks background tasks, and ignores OAuth and keychain, so it needs `ANTHROPIC_API_KEY` or a provider ([headless, bare mode](https://code.claude.com/docs/en/headless#start-faster-with-bare-mode)).
- **HOLDS.** User-invoked skills work: put `/skill-name` in the prompt and it expands. Terminal-only built-ins do not ([headless](https://code.claude.com/docs/en/headless#run-claude-code-programmatically)).
- **NEW.** Marketplace plugins install in the background, so set `CLAUDE_CODE_SYNC_PLUGIN_INSTALL=1` to wait. The `system/init` event lists `plugins` and `plugin_errors`, which CI can assert on ([headless](https://code.claude.com/docs/en/headless#fail-ci-when-a-plugin-or-mcp-server-doesnt-load); [env vars](https://code.claude.com/docs/en/env-vars)).
- **CORRECTED.** `AskUserQuestion` is not simply absent. A `-p` run offers it only when it has a permission host (an SDK `canUseTool` callback or `--permission-prompt-tool`); `--permission-prompts none` removes it ([hooks, AskUserQuestion](https://code.claude.com/docs/en/hooks#askuserquestion); [headless](https://code.claude.com/docs/en/headless#turn-off-permission-prompts-in-unattended-runs)). A `PreToolUse` hook returning `defer` (honoured only in `-p`) ends the run with `stop_reason: "tool_deferred"`, and `claude -p --resume <id>` continues it ([hooks](https://code.claude.com/docs/en/hooks#defer-a-tool-call-for-later)).
- **CHANGED.** Since 2.1.302, `-p` starts in Manual mode when nothing sets a mode, so any call that needs approval is denied unless `--permission-mode` or `--allowedTools` covers it ([headless](https://code.claude.com/docs/en/headless#auto-approve-tools)).
- **NEW.** `Setup` hooks fire only for `--init`/`--maintenance` under `-p` (or `--init-only`), cannot block, and their JSON output is discarded; `SessionStart` can return `initialUserMessage` to start a `-p` run with no prompt ([hooks, Setup](https://code.claude.com/docs/en/hooks#setup)). Plugin monitors do not start under `-p` ([manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference#fields)).

### 9. Sandbox: Chromium, `localhost`, exclusions

- **CORRECTED (scope).** The Bash sandbox is **off by default** (`/sandbox` or `sandbox.enabled`). It covers shell commands and their children; hooks, MCP and LSP servers, file tools and plugin monitors run outside it ([sandboxing](https://code.claude.com/docs/en/sandboxing#what-the-sandbox-restricts); [plugin security](https://code.claude.com/docs/en/plugins/security)).
- **CORRECTED (platform).** Chromium failing with `No usable sandbox!` is documented for **Linux and WSL2** (blocked user namespaces). Fixes: start Chromium with `--no-sandbox`; exclude the command that runs the browser (match the test command, not the browser); or, new in 2.1.305 (20 Oct 2026), set `sandbox.allowNestedUserNamespaces: true` in `~/.claude/settings.json` (user or managed scope, not project) ([sandboxing, Chromium](https://code.claude.com/docs/en/sandboxing#chromium-or-rootless-podman-fails-inside-the-sandbox-on-linux); [settings](https://code.claude.com/docs/en/settings-reference#sandbox-allownestedusernamespaces)).
- **HOLDS, with a macOS branch.** A sandboxed command cannot reach a host dev server. On macOS set `network.allowLocalBinding: true`; on Linux/WSL2 `localhost` is private to the command and `allowLocalBinding` has no effect, so the command must be excluded ([sandboxing, localhost](https://code.claude.com/docs/en/sandboxing#a-command-fails-to-reach-a-server-on-localhost)). `docker` and `watchman` (`jest --no-watchman`) are incompatible; `gh`, `gcloud` and `terraform` may fail TLS on macOS ([sandboxing](https://code.claude.com/docs/en/sandboxing#docker-commands-fail)).
- **How exclusion works.** `sandbox.excludedCommands` uses `Bash(...)` rule syntax, matches the text of the call, and takes a call out of the sandbox only if every command in it matches (2.1.277); redirects, `cd` and `$(...)` keep it sandboxed. Project and local entries are ignored when managed settings or `--settings` set `allowUnsandboxedCommands: false` (2.1.282, 2.1.285) ([sandboxing, excludedCommands](https://code.claude.com/docs/en/sandboxing#run-commands-outside-the-sandbox-with-excludedcommands)). Claude may also retry with `dangerouslyDisableSandbox`, through the normal permission flow ([sandboxing](https://code.claude.com/docs/en/sandboxing#the-unsandboxed-retry-escape-hatch)).
- **CORRECTED (plugins).** A plugin has no way to declare exclusions (see 3b). What it can do: run work from a command hook, MCP server or LSP server, which run unsandboxed with the user's full permissions; or have a setup step write `excludedCommands`/`allowNestedUserNamespaces` into the user's settings with consent. `bin/` programs run through Bash, so they stay sandboxed ([plugin security](https://code.claude.com/docs/en/plugins/security)).
- **HOLDS.** Run `--dangerously-skip-permissions` only inside a container, VM or the `srt` sandbox runtime; auto mode's classifier "is not an isolation boundary" ([sandbox environments](https://code.claude.com/docs/en/sandbox-environments)).

## Implications for the factory

**1. Keep the plugin-level `SubagentStart` hook as the one context channel; add `PreToolUse` as the enforcement channel.** Both reach plugin subagents; agent frontmatter hooks do not. Benefit: one hook set, deterministic across subagent boundaries. Trade-offs: every hook fires for every agent, so each must branch on `agent_type`; injected context is advice, not a gate; keep each injection under 10,000 characters (inject a short rule block plus a file path). Mark `guard-paths.mjs` with `onFailure: "block"` (needs 2.1.295+) so a crash fails closed.

**2. Drop any design dependence on agent-level `hooks`, `mcpServers`, `permissionMode`, `initialPrompt`.** Use plugin-level hooks and `.mcp.json`, and restrict agents with `tools`/`disallowedTools`. Reviewers stay read-only by `tools` plus a `PreToolUse` path guard, not by `permissionMode: plan`.

**3. Handle the worktree base explicitly.** With git-flow feature branches and `isolation: worktree`, the implementer's worktree starts from the default branch and misses unpushed work. `/setup-factory` should write `worktree.baseRef: "head"` into project settings (with consent), or the pipeline should create its own worktree on the feature branch. Benefit of the setting: native cleanup and main-checkout guards. Cost: a project-wide setting that also changes `EnterWorktree` and `--worktree`.

**4. Treat Bash as variable-free.** In skill and agent Markdown, write the literal `${CLAUDE_PLUGIN_ROOT}/scripts/x.mjs` in the command (it is substituted when the skill loads) and pass state paths as arguments. Pair it with `allowed-tools: Bash(${CLAUDE_PLUGIN_ROOT}/scripts/*)` so scripts run without prompts (the grant clears at the next user message). Prefer this to `bin/` while claude.ai/Cowork install matters; `bin/` gives bare commands but blocks those installs. Keep run state in `.factory/`, plugin caches in `${CLAUDE_PLUGIN_DATA}`.

**5. Keep `disable-model-invocation: true` on all but the entry points, with two consequences.** Such skills cannot be preloaded through an agent's `skills:` field, so shared rules for implementer and reviewers must arrive through the `SubagentStart` payload or a file read, or use `user-invocable: false` for the few shared reference skills (their descriptions then stay in the listing). Put the essential instructions in the first 5,000 tokens of each `SKILL.md`; across a long run older skills fall out of the 25,000-token post-compaction budget, so loop caps stay in scripts. Ship the `verify` skill from `/setup-factory` into the project's `.claude/skills/verify/`, without `disable-model-invocation`; a plugin copy will not trigger the pre-commit instruction.

**6. Keep one plugin for v1; use dependencies later only for mandatory pieces.** Dependencies are real, but they auto-install and auto-enable, require git tags and, across marketplaces, an allowlist; there is no optional form. Optional integrations (Linear, Notion, analytics) should remain separate plugins users install on purpose. This supports the design's "keep v1 small".

**7. Do not budget on `totalTokens`.** It is the final request's size. For headless runs, use `--max-budget-usd` and the result's `total_cost_usd`/`modelUsage`, and keep `maxTurns` plus the concurrency and depth limits as hard caps (all work for plugin agents). For interactive runs, a `SubagentStop` hook that sums `usage` from `agent_transcript_path` is workable but undocumented; label the figure "estimate" and isolate the parser in one script.

**8. Use `claude plugin eval` for skill triggering and agent behaviour, not for end-to-end golden tasks.** It gives a no-plugin baseline, JSON for CI and cheap graders. It cannot hold a full pipeline: empty workspace per run, no project config, 200 turns and one hour per run, Bash needs a sandbox and explicit grants, and every run is billed. Keep the golden-task harness as scripts that call `claude -p --plugin-dir`, and add eval cases for the entry skills and for "right agent dispatched" (`tool_used: Agent`, `--ablation none`).

**9. Design the unattended path around no `AskUserQuestion`.** Questions become a GitHub comment plus a stop, which matches "GitHub is the inbox". If an interactive gate is wanted later, use the `defer`/`--resume` round trip. Every unattended command needs `--permission-mode` and `--allowedTools` (Manual is the default since 2.1.302) or the run stalls on denials. Set `CLAUDE_CODE_SYNC_PLUGIN_INSTALL=1`, assert `plugin_errors` is empty, avoid `--bare` unless an API key is intended, and do not rely on plugin monitors under `-p`.

**10.
