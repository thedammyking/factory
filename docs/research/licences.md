# Which borrowed content can a public repo ship?

Ticket: [#3](https://github.com/thedammyking/factory/issues/3). Checked 2026-11-02 against each repo's default branch, using its LICENSE file, package or plugin metadata, and the GitHub licence API. This is a reading of licence texts, not legal advice.

## Answer

1. **Fifteen of the 18 sources can be copied or adapted into a public repo** if we ship their licence text and copyright line: 11 MIT, 1 MIT declared with no LICENSE file (karpathy-skills), 2 Apache-2.0 (impeccable, and anthropics/skills skill by skill), 1 CC BY 4.0 (rebelytics).
2. **Three cannot be copied: marshal-factory** (no licence, so all rights reserved), **claude-squad** (AGPL-3.0, so copied code would put the whole plugin under AGPL) and **base** (FSL-1.1-ALv2, whose non-compete terms travel with every copy until each version converts to Apache-2.0 two years after release).
3. For those three the design needs only ideas (stage rules, a worktree recipe, a handoff layout). Copyright does not extend to ideas, procedures or methods of operation ([17 USC 102(b)](https://www.copyright.gov/title17/92chap1.html)), so we reimplement them in our own words and code.
4. Permissive repos hide exceptions: BMAD reserves its trademarks, ECC ships a CC BY-SA skill inside an MIT repo, anthropics/skills has no repo-level licence and four proprietary skills, and several repos vendor third-party text. Check the nearest LICENSE before copying any file.

## Implications for the factory

**Keep: borrow MIT and Apache material, with a provenance trail.** Most of the fifteen copyable sources cost one notice each. Only two takes are verbatim in the catalogue (mattpocock `grilling`, ponytail's hook and map scripts); the rest are adapted or reimplemented, so the notices burden is small.
- Ship a root `THIRD_PARTY_NOTICES.md`: source URL, commit SHA copied from, licence, copyright line, files, and `copied`, `adapted` or `idea`. Put the full licence text once per licence.
- Add a one-line header to each copied or adapted file: "Adapted from <URL> (MIT, (c) name). Modified: <what>." Apache-2.0 section 4(b) makes the modified-file marker mandatory for impeccable and skill-creator files.
- Record the SHA because licences move: base changed from PolyForm Noncommercial to FSL, and marshal-factory was created 2026-10-23 with no licence yet ([API](https://api.github.com/repos/ski043/marshal-factory)), so a licence can change or appear at any time.
- Benefit: one place to audit, and the repo can go public with no unknowns. Trade-off: every refresh from upstream must update the file; a stale SHA is a quiet lie.

**Change: reword four "steal" verdicts in the catalogue to "reimplement".**
- marshal-factory: keep the ideas (stage reporting, evidence pinned to a SHA, merge from hard facts), write our own playbook text and our own `.factory/setup.json` field names. Benefit: no licence dependency. Trade-off: slower, and we lose exact wording the author tested. If wording matters, ask for a licence via an issue first.
- claude-squad: write the worktree helper from the git docs (add from a recorded base SHA, remove, prune), roughly ten lines of shell. Benefit: the plugin stays permissive instead of AGPL. Trade-off: we rediscover the orphaned-directory edge case their file handles; git's `prune` doc covers it.
- base: design our own handoff template and never open `starter-commands.toml` while writing it. Benefit: no FSL terms on a public repo. Trade-off: our section list will look similar by necessity; that is fine, because a list of headings is an idea.
- karpathy-skills: write the four rules in our own words and link the repo and post. Benefit: sidesteps the missing copyright line. Trade-off: none worth naming.

**Change: names and brands.** Do not name any skill or agent after a source: `setup-matt-pocock-skills`, anything with BMad, `impeccable-*`, `ponytail`. BMAD forbids it in writing; Apache-2.0 section 6 withholds Impeccable's marks; the MIT texts say nothing on names, so avoiding them there is a precaution, not a rule. Benefit: no endorsement confusion. Trade-off: users lose the cue that a skill is a known one, which a credit line in the notices file restores.

**Change: copy single files, not directories, from big repos.** ECC (CC BY-SA skill inside an MIT repo), anthropics/skills (four proprietary skills, no root licence), wshobson (third-party plugin) and superpowers (vendored Anthropic doc) each contain files the root licence does not clearly cover. Rule: before copying, check the file's folder and its parent for a LICENSE, NOTICE or CREDITS file, and read the plugin manifest's `license` and `author`. Benefit: avoids the share-alike and proprietary traps. Trade-off: a two-minute check per file.

**Decide (owner's call): the factory's own licence.** Apache-2.0 lets us add our own terms to a derivative work as a whole as long as the Apache conditions are still met (LICENSE section 4, closing paragraph, [text](https://github.com/pbakaus/impeccable/blob/main/LICENSE)), so MIT for our files works; the Apache-2.0 files (impeccable, skill-creator scripts) stay Apache inside their own folders with their LICENSE beside them. My default is MIT for our code. Apache-2.0 would add a patent grant and make the mixed folders match, at the cost of heavier notice duties for downstream users. The other route is to avoid vendoring Apache files at all: call `npx impeccable detect` as a tool and write our own eval loop, which keeps the repo single-licence. CC BY 4.0 text, if ever adapted, should live in a marked prose file, not in scripts.

**Not covered here.** The catalogue also says "steal" from entries outside this ticket and not checked: cursor/plugins (pstack, which marshal-factory's playbook also extends), anthropics/claude-plugins-official, agentskills, vercel-labs/skills, nvk/llm-wiki, haydenschmitty/floorplan, headroom, herdr and the Karpathy llm-wiki gist. Give them the same check before any file from them lands in the repo.
