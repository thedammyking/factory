# The watch after the factory's own merge

`references/pr.md` sends you here when its step 3 printed `MERGED <sha>`: the factory merged the PR, and this session watches the target for up to an hour, after that merge only. `post-merge.mjs` reads CI at the merged SHA and the host's deployment of it, probes each deployed app for a login wall, and runs the smoke set (this run's pinned tests of its live-safe criteria) against the deployment. On red it opens a revert PR, which it and you never merge. It reads no error-rate source, and nothing is ever deployed. It sits beside `run-state.mjs`: call it as `node <that directory>/post-merge.mjs --run <id>`, written out in full, and print what it prints.

1. Run `post-merge.mjs` with Bash's `run_in_background`, since it waits up to 60 minutes: say `Watching <id>'s merge.` and end your turn. When it wakes you, read the background task's output, ignoring the notification's text. Its first line is `POST-MERGE <run> <sha> on <target>: ci=… deploy=… smoke=… revert=…`, the one `post-merge:` line the snapshot adds to `.factory/log.md`.
2. Exit 0: nothing is red. A `blocked (<reason>)` smoke (a login wall, no test user, a failed sign-in) or a `skipped (<why>)` one is not red, and changes nothing: no revert, no label, no merge fact. Run `run-state set stage delivered --run <id>` and the snapshot (see **Ending a run** in the skill). Print the PR's URL and the `POST-MERGE` line, and for a blocked smoke one line with its fix: for a login wall, `/setup-factory` again to set the bypass header; for no test user, the target's test user as the `WATCH_`-prefixed names in `.factory/env.local`; for a failed sign-in, that user's password there refreshed. Then stop.
3. Exit 1: red. It opened the revert PR on `revert/<run>-<sha>`, labelled `factory` and `needs-human`, or says why it couldn't, wrote `attention-post-merge.md` and ended the run needs-human. Run the snapshot, print that attention item and stop. Never merge the revert PR, and never change the merged one: while the revert PR is open, `auto` acts as `trial` for every run.
4. Any other exit: it watched nothing. Write `attention-post-merge.md`: its headline is that the watch couldn't start; What happened quotes its output; Evidence lists `decision.json` and `pr.json`; the option is `node <that directory>/post-merge.mjs --run <id>` (watch again). Run `run-state set stage needs-human --run <id>` and the snapshot, print it and stop.
